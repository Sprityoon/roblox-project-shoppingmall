# Roblox UI/UX

로블록스 UI가 지저분해 보이는 이유는 거의 항상 같다: 값이 제각각이고(색·간격·모서리), 화면 크기마다 깨지고, 눌렀을 때 반응이 없다. 이 스킬은 그 세 가지를 구조적으로 막는다.

작업 순서는 항상 **토큰 → 레이아웃 → 컴포넌트 → 모션 → 기기 검증**이다. 예쁘게 만드는 것보다 일관되게 만드는 것이 먼저다. 일관성만 지켜도 대부분의 로블록스 게임보다 깔끔해 보인다.

## 1. 먼저 확인할 것

- 프로젝트에 이미 테마 모듈(`Theme`, `UIConfig` 등)이나 컴포넌트 폴더가 있는지 찾아보고, 있으면 그 값을 따른다. 새 체계를 덧씌우면 두 가지 스타일이 섞여 더 지저분해진다.
- 없으면 `references/ui-kit.md`의 `Theme`, `Motion`, `Button` 모듈을 `ReplicatedStorage/UI/` 아래에 먼저 만든 뒤 화면 작업을 시작한다.
- 화면의 목적을 한 문장으로 정한다("플레이어가 유닛을 사게 한다"). 그 목적에 필요 없는 요소는 넣지 않는다.

## 2. 디자인 토큰: 숫자를 직접 쓰지 않는다

색, 간격, 모서리 반경, 글자 크기, 애니메이션 시간은 전부 `Theme` 모듈에서 가져온다. 화면 코드에 `Color3.fromRGB(...)`나 `UDim.new(0, 13)` 같은 날것의 값이 보이면 토큰으로 바꾼다. 나중에 테마를 한 번에 바꿀 수 있고, 무엇보다 값이 몇 개로 제한되어 화면이 정돈돼 보인다.

- **간격**: 4의 배수만 쓴다(4, 8, 12, 16, 24, 32). 요소 사이 간격보다 그룹 사이 간격을 크게 줘서 묶음이 눈에 보이게 한다.
- **색**: 배경 2~3단계, 텍스트 2단계(기본/흐림), 강조색 1개, 상태색 3개(성공/경고/위험)로 충분하다. 강조색은 화면당 가장 중요한 행동 하나에만 쓴다. 전부 강조하면 아무것도 강조되지 않는다.
- **모서리**: 화면 전체에서 반경을 2~3종으로 통일한다. 바깥 패널 반경 ≥ 안쪽 요소 반경.
- **글자**: 크기 4단계(Display/Title/Body/Label), 굵기 2종. 폰트는 한 가족만 쓴다.
- **대비**: 텍스트와 배경의 명도 차를 충분히 둔다. 3D 월드 위에 직접 뜨는 텍스트는 배경이 계속 바뀌므로 `UIStroke`나 반투명 판을 깐다.

## 3. 레이아웃: 손으로 좌표를 찍지 않는다

**좌표 계산 대신 레이아웃 객체에 맡긴다.** 요소를 추가·삭제해도 정렬이 유지되고, 텍스트 길이가 바뀌어도(번역 포함) 깨지지 않는다.

| 목적 | 쓸 것 |
|---|---|
| 한 줄/한 열로 나열 | `UIListLayout` (`Padding`, `FillDirection`, `HorizontalFlex`/`VerticalFlex`) |
| 남는 공간 채우기 | 자식에 `UIFlexItem` (`FlexMode = Fill`) |
| 격자(인벤토리, 상점) | `UIGridLayout` + `UIAspectRatioConstraint` |
| 안쪽 여백 | `UIPadding` (컨테이너마다 하나) |
| 내용에 맞춰 크기 결정 | `AutomaticSize` (텍스트 버튼, 툴팁, 리스트 높이) |
| 비율 고정 | `UIAspectRatioConstraint` (아이콘, 카드, 정사각 버튼) |
| 크기 상·하한 | `UISizeConstraint`, 텍스트는 `UITextSizeConstraint` |
| 스크롤 | `ScrollingFrame` + `AutomaticCanvasSize = Y`, `CanvasSize = 0,0,0,0` |

**Scale과 Offset 구분**: 화면을 나누는 큰 영역(패널 위치, 전체 폭 비율)은 Scale, 그 안의 간격·모서리·글자·아이콘은 Offset으로 잡고, 루트에 `UIScale` 하나를 달아 뷰포트에 맞춰 전체를 한 번에 키우고 줄인다(`references/ui-kit.md`의 `AutoScale`). 전부 Scale로 잡으면 화면 비율이 바뀔 때 버튼이 찌그러지고 간격이 제각각이 되며, 전부 Offset으로만 잡고 스케일링이 없으면 휴대폰에서 콩알만 해진다.

**앵커**: 요소는 붙어 있어야 할 모서리에 고정한다. 우상단 HUD는 `AnchorPoint = (1, 0)`, `Position = UDim2.new(1, -16, 0, 16)`. 가운데 모달은 `AnchorPoint = (0.5, 0.5)`, `Position = UDim2.fromScale(0.5, 0.5)`.

**ScreenGui 기본 설정** (새로 만들 때마다):
- `ResetOnSpawn = false`: 리스폰 때 UI가 초기화되어 상태가 날아가는 것을 막는다.
- `ZIndexBehavior = Sibling`: 부모-자식 순서대로 그려져 겹침을 예측할 수 있다.
- `IgnoreGuiInset`는 전체 화면 배경(로딩, 페이드)에만 켠다. 일반 UI는 꺼둬야 상단 바·노치와 겹치지 않는다. 세밀하게는 `ScreenInsets`로 조절한다.
- `DisplayOrder`는 층별로 약속을 정한다: HUD 0, 메뉴 10, 모달 20, 토스트 30, 로딩/전환 100.
- 화면 하나당 ScreenGui 하나로 나눈다. 켜고 끄기 쉽고, 한 화면의 변경이 다른 화면의 재레이아웃을 일으키지 않는다.

## 4. 모바일이 기준이다

로블록스 플레이어 대부분이 휴대폰이다. PC에서 예쁜 UI가 아니라 휴대폰에서 쓸 수 있는 UI를 먼저 만들고 넓은 화면으로 확장한다.

- **터치 타겟**: 스케일 적용 후 실제 화면에서 44px 이상. 보이는 아이콘이 작아도 투명한 버튼 영역은 크게 잡는다. 버튼 사이는 8px 이상 띄운다.
- **엄지 영역**: 자주 누르는 버튼은 화면 아래쪽 좌우에. 단, 좌하단은 이동 조이스틱, 우하단은 점프 버튼이 차지하므로 그 자리는 비운다. 상단 좌측은 로블록스 기본 메뉴 자리다.
- **안전 영역**: 노치·둥근 모서리·홈 바에 가려지지 않게 가장자리에서 여백을 둔다(`ScreenInsets` 기본값이 대부분 처리해 준다).
- **호버에 의존하지 않는다**: 터치에는 호버가 없다. 툴팁으로만 볼 수 있는 정보는 탭으로도 볼 수 있어야 한다.
- **입력 분기**: 클릭은 `MouseButton1Click` 대신 `Activated`를 쓴다(마우스·터치·게임패드 모두 처리). 키 안내("E를 눌러")는 현재 입력 장치에 맞춰 바꾼다. 게임패드/콘솔을 지원한다면 `Selectable`과 선택 순서를 확인한다.
- **가로 화면 기준**으로 설계하되, 세로로 긴 리스트는 스크롤로 처리한다.

## 5. 컴포넌트: 한 번 만들고 재사용한다

같은 모양의 버튼을 화면마다 새로 만들면 조금씩 달라진다. 버튼, 패널, 모달, 토스트, 재화 표시 같은 반복 요소는 함수 하나(`Button.new(props)`)로 만들어 `ReplicatedStorage/UI/Components`에 두고 모든 화면이 그것을 쓴다. 뼈대는 `references/ui-kit.md`에 있다.

모든 누를 수 있는 요소는 네 가지 상태를 가진다. 하나라도 빠지면 "먹통" 같은 느낌이 난다.

| 상태 | 표현 |
|---|---|
| 기본 | 토큰 색 |
| 호버(PC) | 살짝 밝게 |
| 눌림 | 0.96배로 축소 + 살짝 어둡게, 0.1초 이내 |
| 비활성 | 채도·불투명도 낮춤, `Active = false`, 왜 못 누르는지 알려줌 |

`AutoButtonColor`는 끄고 직접 상태를 그린다. 기본 효과는 토큰 색과 어울리지 않는다.

## 6. 모션: 짧고, 이유 있게

애니메이션은 "무엇이 바뀌었는지" 알려주기 위한 것이다. 장식용으로 길게 넣으면 반복 플레이에서 방해가 된다.

- 시간: 누름 반응 0.1초, 일반 전환 0.2초, 큰 패널 0.3초. 0.4초를 넘기지 않는다.
- 이징: 나타날 때 `Quad`/`Quint` `Out`, 사라질 때 `In`. `Back Out`은 팝업 등장처럼 한두 곳에만.
- 나타남/사라짐은 위치 이동보다 **스케일(0.9→1) + 투명도** 조합이 깔끔하다. 여러 자식을 함께 페이드하려면 `CanvasGroup.GroupTransparency`를 쓴다(자식마다 투명도를 트윈하지 않아도 된다).
- 숫자(재화, 점수)는 순간이동시키지 말고 0.3초쯤 카운트업한다. 획득량이 눈에 들어온다.
- `GuiService.ReducedMotionEnabled`가 켜져 있으면 이동·확대는 생략하고 페이드만 한다.
- 트윈은 `references/ui-kit.md`의 `Motion` 헬퍼 하나를 거치게 해서 시간·이징이 통일되게 한다.

## 7. UX 원칙

화면별 흐름(첫 접속, HUD 구성, 상점, 오류 처리 등)의 구체적인 지침은 `references/ux-flows.md`에 있다. 새 화면을 설계하거나 기존 흐름을 손볼 때 읽는다. 핵심만:

- **모든 입력에 0.1초 안에 반응한다.** 서버 응답을 기다려야 하면 버튼을 즉시 "처리 중" 상태로 바꾸고, 결과가 오면 확정하거나 되돌린다.
- **한 화면에 주요 행동은 하나.** 나머지는 보조 스타일로 낮춘다.
- **HUD는 최소로.** 지금 결정에 필요한 정보만 상시 표시하고 나머지는 메뉴 안으로 넣는다.
- **첫 30초 안에 플레이가 시작된다.** 긴 설명 창 대신 하면서 배우게 한다.
- **닫는 방법이 항상 보인다.** 모달은 X 버튼, 바깥 탭, (PC) Esc/(패드) B 모두로 닫힌다.
- **되돌릴 수 없는 행동(로벅스 결제, 아이템 삭제)만 확인을 묻는다.** 전부 묻으면 아무도 읽지 않는다.

## 8. 성능

- 매 프레임(`RenderStepped`)마다 UI 속성을 쓰지 않는다. 값이 바뀔 때만 갱신한다.
- 긴 리스트(100개 이상)는 한 번에 다 만들지 말고 보이는 만큼만 만들거나 페이지로 나눈다.
- `CanvasGroup`, `UIStroke`가 붙은 큰 텍스트, `ClipsDescendants` 중첩은 비용이 있다. 필요한 곳에만 쓴다.
- 닫힌 화면은 `Enabled = false`로 끈다(투명하게만 만들면 계속 계산된다).
- 이미지 아이콘은 표시 크기의 2배 정도 해상도면 충분하다.

## 9. 끝내기 전 검증

Studio의 **Device Emulator**로 최소 세 가지를 확인하고, 확인하지 못한 것은 사용자에게 말한다. Roblox Studio MCP가 연결돼 있으면 Studio 쪽 스킬 `rbx-device-simulator-lua`를 불러와(`skill` 도구) 기기를 바꿔 가며 `screen_capture`로 실제 화면을 찍어 본다. 코드만 보고 "괜찮을 것"이라고 판단하지 않는다.

1. 작은 휴대폰 가로(예: 667×375): 터치 타겟 크기, 글자 가독성, 조이스틱/점프 버튼과 겹침
2. 태블릿(4:3): 비율이 달라져도 찌그러지거나 비지 않는지
3. PC 1920×1080 및 울트라와이드: 요소가 과하게 커지거나 양 끝으로 벌어지지 않는지

추가로: 가장 긴 텍스트(큰 숫자 `999,999,999`, 긴 닉네임, 번역문)를 넣어 넘침 확인, 리스폰 후 UI 유지 확인, 빠르게 연타했을 때 중복 실행되지 않는지 확인.

## 흔한 실수

- `TextScaled = true` 남용: 글자 크기가 요소마다 달라져 지저분해진다. 고정 `TextSize` + 루트 `UIScale`을 기본으로 하고, 꼭 필요할 때만 `UITextSizeConstraint`와 함께 쓴다.
- 서버 스크립트에서 UI 조작: UI는 `LocalScript`/클라이언트 모듈에서만 다룬다. 서버는 데이터만 보내고 클라이언트가 그린다.
- 클라이언트 UI 상태를 믿고 서버 처리: 버튼을 비활성화했다고 요청이 안 오는 게 아니다. 가격·보유량 검증은 서버에서 다시 한다.
- `wait()`로 애니메이션 타이밍 맞추기: `Tween.Completed`나 `task.delay`를 쓴다.
- 이벤트 연결을 정리하지 않음: 화면을 파괴할 때 연결도 끊는다(인스턴스를 `Destroy`하면 그 인스턴스의 연결은 끊기지만, 외부 시그널에 건 연결은 직접 끊어야 한다).
