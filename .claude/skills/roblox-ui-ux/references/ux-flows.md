# 화면별 UX 지침

새 화면을 설계하거나 기존 흐름을 고칠 때 해당 절만 읽는다.

목차
1. 첫 접속(FTUE)
2. HUD
3. 메뉴·모달
4. 상점·결제
5. 인벤토리·리스트
6. 피드백과 보상 연출
7. 대기·오류·빈 상태
8. 텍스트와 숫자
9. 접근성

## 1. 첫 접속(FTUE)

로블록스 플레이어는 재미를 못 느끼면 1분 안에 나간다. 첫 세션의 목표는 설명이 아니라 **첫 성공 경험**이다.

- 접속 후 30초 안에 조작이 시작되게 한다. 로딩 화면이 길면 진행률과 팁 한 줄을 보여준다.
- 글로 된 튜토리얼 창을 띄우지 않는다. 지금 눌러야 할 것 하나를 화살표·하이라이트로 가리키고, 해내면 다음 것을 가리킨다.
- 처음에는 HUD를 거의 비워두고, 기능을 처음 쓰게 되는 시점에 해당 버튼을 등장시킨다. 한꺼번에 20개 버튼을 보여주면 아무것도 안 누른다.
- 첫 2분 안에 눈에 띄는 보상(레벨업, 첫 아이템)을 한 번 준다.
- 튜토리얼은 건너뛸 수 있어야 하고, 재접속했을 때 처음부터 다시 시작하지 않아야 한다(진행 단계를 저장).
- 상점·결제 유도 팝업은 첫 세션 초반에 띄우지 않는다.

## 2. HUD

- 상시 표시는 "지금 판단에 쓰는 정보"만: 체력, 핵심 재화 1~2종, 현재 목표.
- 배치 관례를 따른다: 재화·설정은 상단, 목표는 좌측 또는 상단 중앙, 행동 버튼은 우하단(점프 버튼 위/옆), 좌하단은 조이스틱 자리라 비운다.
- 화면 중앙 40%는 게임 월드를 위해 비운다.
- 관련 정보는 묶고 묶음끼리는 띄운다. 묶음마다 반투명 판을 깔지, 판 없이 띄울지 한 가지로 통일한다.
- 값이 바뀔 때만 잠깐 강조(살짝 커졌다 돌아옴, 색 번쩍)해서 시선을 끈다.
- 전투·컷신처럼 집중이 필요한 순간에는 불필요한 HUD를 숨긴다.

## 3. 메뉴·모달

- 한 번에 모달 하나. 모달 위에 모달이 필요하면 화면 구조를 다시 생각한다(확인창만 예외).
- 닫기: X 버튼(우상단, 터치 타겟 44px 이상), 바깥 탭, Esc/패드 B. 셋 다 된다.
- 열릴 때 뒤 화면을 어둡게 해서 초점을 옮긴다. 열린 동안 뒤의 버튼은 눌리지 않아야 한다.
- 제목 → 내용 → 행동 버튼 순서. 주 버튼은 오른쪽(또는 아래), 취소는 왼쪽에 보조 스타일로.
- 탭이 5개를 넘으면 분류를 다시 한다. 선택된 탭은 색과 밑줄/배경 두 가지로 표시한다.
- 모달이 열려 있는 동안 캐릭터 조작을 막을지 결정하고 일관되게 적용한다.

## 4. 상점·결제

- 상품 카드: 아이콘, 이름, 효과 한 줄, 가격. 가격은 재화 아이콘과 함께 버튼 안에 표시한다.
- 살 수 없으면 버튼을 비활성화하고 이유를 보여준다("골드 120 부족"). 부족분을 채울 방법으로 가는 길을 준다.
- 구매 버튼을 누르면 즉시 처리 중 표시 → 서버 확정 후 성공 연출. 서버에서 가격·보유량·중복 구매를 다시 검증한다.
- 게임 내 재화 소비는 확인창 없이, 로벅스 결제와 되돌릴 수 없는 소모만 확인한다(로벅스 결제는 로블록스 자체 확인창이 뜬다).
- 뽑기류는 확률을 표시한다(로블록스 정책상 필요). 가짜 타이머, 닫기 버튼 숨기기, 실수 유도 배치 같은 속임수 패턴은 쓰지 않는다. 주 이용자가 어린이이고 플랫폼 정책 위반이 될 수 있다.
- 이미 보유한 상품은 "보유 중"으로 구분한다.

## 5. 인벤토리·리스트

- 격자는 `UIGridLayout`, 칸은 정사각형. 휴대폰 가로에서 한 줄 4~6칸이 손가락으로 누르기 적당하다.
- 등급은 테두리 색 + 아이콘 모서리 표식 두 가지로 표시한다(색만으로 구분하지 않는다).
- 선택 → 상세 패널에 정보와 행동 버튼. 길게 누르기·더블탭에만 의존하는 기능은 만들지 않는다.
- 항목이 많으면 정렬/필터를 주고, 새로 얻은 항목에는 표식을 붙였다가 확인하면 지운다.
- 비어 있으면 빈 격자 대신 안내("아직 유닛이 없어요. 상점에서 뽑아보세요")와 이동 버튼을 보여준다.

## 6. 피드백과 보상 연출

손맛은 UI에서 절반이 나온다. 다만 자주 반복되는 행동일수록 연출은 짧아야 한다.

- 버튼: 눌림 축소 + 짧은 클릭음. 소리는 `SoundService:PlayLocalSound`로 로컬 재생한다.
- 재화 획득: 숫자 카운트업 + 획득량 "+50"이 떠올랐다 사라짐.
- 큰 보상(레벨업, 희귀 획득): 화면 중앙 연출 1~2초, 탭하면 건너뛴다.
- 실패/불가: 좌우로 짧게 흔들림 + 낮은 효과음 + 이유 토스트.
- 한 번에 여러 보상이 오면 순서대로 줄 세우지 말고 하나의 요약 창으로 묶는다.

## 7. 대기·오류·빈 상태

- 0.3초 이상 걸릴 수 있는 요청은 처리 중 표시를 한다. 그동안 같은 버튼을 다시 누를 수 없게 한다.
- 서버 요청에는 타임아웃을 두고, 실패하면 원래 상태로 되돌린 뒤 사람 말로 알린다("구매에 실패했어요. 다시 시도해 주세요"). 오류 코드만 보여주지 않는다.
- 데이터 로딩이 끝나기 전에는 0이나 빈 값을 보여주지 말고 자리 표시(스켈레톤, "…")를 보여준다. 재화가 0으로 보였다가 바뀌면 불안을 준다.
- 데이터 저장 실패처럼 심각한 상황은 토스트가 아니라 사라지지 않는 안내로 알린다.

## 8. 텍스트와 숫자

- 문장은 짧게, 버튼은 동사로("구매", "장착", "닫기").
- 큰 수는 축약한다(1,234 → 1.2K, 1,234,567 → 1.2M). 축약 규칙을 함수 하나로 통일한다.
- 숫자가 바뀔 때 폭이 흔들리지 않게 고정 폭 영역에 오른쪽 정렬한다.
- 긴 닉네임·번역문은 `TextTruncate = AtEnd`로 자르거나 `AutomaticSize`로 늘어나게 한다. 둘 중 무엇을 쓸지 요소마다 정한다.
- 여러 언어를 지원할 계획이면 문자열을 코드에 흩어놓지 말고 한 테이블에 모은다(로블록스 자동 번역·LocalizationTable 활용).
- 사용자가 입력한 텍스트를 다른 플레이어에게 보여줄 때는 서버에서 `TextService` 필터링을 거친다(정책상 필수).

## 9. 접근성

- 색만으로 정보를 전달하지 않는다(빨강/초록 구분 + 아이콘·글자).
- 본문 글자는 실제 화면에서 너무 작지 않게(휴대폰에서 읽히는지 직접 확인).
- `GuiService.ReducedMotionEnabled`, `GuiService.PreferredTransparency` 같은 플레이어 설정을 존중한다.
- 화면 번쩍임·강한 흔들림은 짧고 약하게.
- 게임패드 지원 시 모든 버튼에 선택 이동이 닿는지, 화면이 열릴 때 첫 선택 대상이 지정되는지 확인한다.
