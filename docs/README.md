# 문서 폴더 사용법

사람과 여러 AI 에이전트가 같은 프로젝트에 번갈아 붙어도 서로의 작업을 덮어쓰지 않고 이어갈 수 있게 하는 공용 기록이다. 대화 내용은 세션이 끝나면 사라지므로, 다음 사람이 알아야 할 것은 전부 여기에 남긴다.

## 구조

| 파일 | 내용 | 누가 고치나 |
|---|---|---|
| [plan/game-design.md](plan/game-design.md) | 기획: 무엇을 만드는가 | 사용자 결정. 에이전트는 제안만 하고, 사용자가 승인한 내용만 반영 |
| [plan/tasks.md](plan/tasks.md) | 작업할 내용: 할 일 목록과 우선순위 | 누구나. 완료 시 체크 |
| [log/NOW.md](log/NOW.md) | 지금 진행 중인 작업과 담당자 | 작업을 시작·종료하는 쪽 |
| [log/2026-11.md](log/2026-11.md) | 작업 로그(월별 파일, 아래로만 추가) | 작업을 끝낸 쪽 |
| [ideas/ideas.md](ideas/ideas.md) | 나중에 구현 여부를 결정할 아이디어 | 누구나 추가. 채택은 사용자 |

## 작업 순서

1. **시작 전에 읽는다**: `log/NOW.md`(누가 무엇을 건드리고 있는지) → `plan/tasks.md`(무엇을 할 차례인지). 기획 배경이 필요하면 `plan/game-design.md`.
2. **작업을 잡는다**: `log/NOW.md`에 한 줄을 추가한다. 다른 담당자가 같은 스크립트·화면을 잡고 있으면 건드리지 않고 사용자에게 알린다.
3. **작업한다.**
4. **끝나면 기록한다**: `log/NOW.md`에서 자기 줄을 지우고, 이번 달 로그 파일 맨 아래에 항목을 추가하고, `plan/tasks.md`의 해당 작업을 체크한다.
5. **하다가 떠오른 것은 구현하지 말고** `ideas/ideas.md`에 적는다. 요청받지 않은 기능을 슬쩍 넣으면 범위가 불어난다.

## 규칙

- 로그는 고치지 않고 아래에 덧붙이기만 한다. 틀린 내용은 새 항목으로 정정한다.
- 로그에는 "무엇을, 어디에(Studio 경로 또는 파일 경로), 확인한 것과 못 한 것"을 적는다. 다음 사람이 그 항목만 읽고 이어갈 수 있어야 한다.
- 작업 ID(`T-001`)는 한 번 붙이면 바꾸지 않는다. 로그와 대화에서 그 ID로 가리킨다.
- 담당자 표기: 사용자는 `사용자`, 에이전트는 도구 이름(`Claude Code`, `Codex`, `Studio Assistant` 등).
- 달이 바뀌면 새 로그 파일(`log/YYYY-MM.md`)을 만든다.
- 파일·폴더 이름은 영문으로 쓴다(이 PC에서 한글 경로 때문에 도구가 실패한 적이 있다). 내용은 한국어.
