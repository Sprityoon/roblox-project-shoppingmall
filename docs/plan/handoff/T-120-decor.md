# T-120 맵 2차 꾸미기

## 목적

배치는 괜찮지만 화이트박스 티가 나는 맵을 MVP로 내놓을 수 있는 모습으로 만든다. 1차(조명, 바닥·소품 재질, NPC, 천장과 조명 기구)는 끝났다. 남은 것은 **정리, 상점 천장, 간판, 상품과 소품**이다. 근거: design-details.md 14번, 사용자 의견(2026-11-12 "텍스처나 부가 작업이 없어 MVP로 쓰기 아쉽다").

A·B·C는 서로 독립이고 다른 카드와도 겹치지 않아 언제든 할 수 있다. D는 알바(T-116)의 표식이 놓인 뒤에 하는 것이 안전하다.

## 지금 상태

- 맵: `Workspace.Mall` (220×160). 바닥 윗면 Y=1(구역 바닥은 Y=1.2), 2층 바닥 Y=24~25, 천장 아랫면 Y=49. 색은 파스텔, 구역마다 대표색(`Config.Zones`).
- 조명: `Workspace.Mall.Lights/<구역 id>`. 구성과 주의점은 structure.md "조명 구성". **바닥이 밝아 조명을 더하면 화면이 쉽게 하얗게 날아간다.**
- 마트·장난감 가게·창고·전기실은 벽(Y=1~24) 위가 뚫려 있고 조명 레일(`LightRail`, Y=24.3)만 지나간다. 북쪽의 커뮤니티 센터·패션 상점·아케이드는 2층 바닥이 천장 역할을 한다.
- 진열대, 탁자, 마네킹, 오락기는 색만 칠한 상자다. 상품이 없다.

## A. 정리 (사용자 승인: 2026-11-13)

1. `Workspace.Baseplate`를 **지운다**.
2. 유리문(`Structure.EntranceDoors`, z=79) 밖으로 보이는 부분만 새로 만든다: 문 앞 바닥(예: 80×1×40, 윗면 Y=1, 보도 느낌)과 화단 몇 개, 멀리 보이는 배경(파스텔 건물 실루엣 판 정도). 플레이어는 나갈 수 없으니 문 안쪽에서 보이는 범위만 만든다. `Structure.Outside` 폴더에 둔다.
3. `ServerStorage.MapArchive`를 **지운다**(교체 전 NPC 표식, 창고 입구 막대). 저장된 이전 버전에는 남아 있다.
4. 지운 뒤 플레이 테스트로 스폰과 이동에 문제가 없는지 본다.

## B. 상점 천장 (사용자 승인: 2026-11-13)

마트, 장난감 가게, 창고, 전기실에 천장을 덮는다.

- 각 구역 모델(`Zones.Mart` 등) 안에 `Ceiling` 파트: 구역 벽 안쪽을 덮는 크기, 아랫면 Y=24, 두께 1(윗면이 2층 바닥과 같은 Y=25). 색은 따뜻한 흰색, `CastShadow = false`(이 맵의 조명 방식. structure.md 참고).
- 기존 조명 레일은 천장과 겹치므로, 북쪽 상점처럼 천장 밑면에 붙는 판 조명으로 바꾸거나 레일을 천장 바로 아래로 내린다. **`Lights/<구역 id>` 폴더 구조와 이름은 유지한다**(대정전이 구역 폴더 단위로 켜고 끈다).
- 덮고 나면 방 안이 어두워지거나 하얗게 날아가지 않는지 구역마다 캡처로 확인하고 밝기를 맞춘다.
- 2층에서 뛰어서 지붕 위로 올라갈 수 있게 되는데 막지 않아도 된다. 지붕 위에는 아무것도 두지 않는다.
- 대정전을 한 번 돌려서 구역 불이 꺼지고 켜지는 것이 방 안에서 또렷이 보이는지 확인한다.

## C. 간판

- 문구를 확정 기획에 맞춘다(제목 줄은 그대로, 아래 설명 줄만).

  | 간판 | 지금 | 바꿀 문구 |
  |---|---|---|
  | 마트 | 신선 식품 · 간식 · 소품 | 간식 · 진열 알바 |
  | 장난감 가게 | 인형 · 장난감 · 컬렉션 | 풍선 · 손전등 색 |
  | 패션 상점 | 코스튬 · 액세서리 꾸미기 | 발자취 · 반짝이 · 칭호 |
  | 커뮤니티 센터 | 휴식 · 모임 · 이벤트 안내 | 게시판 · 휴식 |
  | 아케이드 | 미니게임 · 코인 획득 | 곧 열어요! |
  | 전기실 | 전력 관리 · 대정전 수리 구역 | 그대로 |

- 무대 배경은 제목만 둔다(설명 줄은 사용자 요청으로 지웠다. 다시 넣지 않는다). 창고 간판은 이미 고쳤다.
- 입구 간판(`Zones.Entrance.EntranceSign`): 몰 안쪽을 보는 면에 환영 문구가 오게 한다(지금은 벽 쪽 면에 있다).
- 설명 줄 글씨가 복도에서(약 40 studs) 읽히게 키운다. 캡처로 확인한다.
- 간판의 `SurfaceGui`는 손님이 다니는 쪽 면을 봐야 한다(2026-11-12에 6곳을 고쳤다. 다시 뒤집지 않는다).

## D. 상품과 소품

구역마다 "무슨 가게인지 한눈에 보이게" 한다. 아래는 최소 목록이고, 더 넣어도 된다.

| 구역 | 넣을 것 |
|---|---|
| 마트 | 진열대 옆면의 선반 칸과 상품 줄, 냉장 진열장(북쪽 벽), 과일 상자, 장바구니 더미, 계산대의 계산기. **진열대 윗면은 비워 둔다**(알바의 진열 칸) |
| 장난감 가게 | 벽 선반과 장난감, 풍선 다발(파는 풍선과 같은 색들), 인형, 가운데 전시대 꾸미기 |
| 패션 상점 | 마네킹 다듬기, 옷걸이 봉과 옷, 거울, 러그, 탈의실 커튼 |
| 커뮤니티 센터 | 게시판에 포스터(스탬프 카드·출석 자리, T-118에서 실제 내용), 소파와 탁자 다듬기, 화분, 책장 |
| 아케이드 | **닫힌 가게**: 입구에 "곧 열어요" 배너와 안내 줄, 오락기는 어둡게, 안쪽은 들어갈 수 있되 할 것은 없다 |
| 창고 | 상자 더미와 선반 랙, 팔레트. 알바의 상자 자리 주변 4 studs는 비운다 |
| 전기실 | 발전기 다듬기, 배관, 경고 줄무늬, 제어판 |
| 광장 | 벤치, 분수 다듬기(물줄기), 화분 |
| 무대 | 커튼, 바닥 테두리 |
| 복도 | 벽 아래 걸레받이와 기둥, 상점 입구 앞 바닥에 구역 대표색 띠, 벤치, 쓰레기통 |
| 입구 | 매트, 화분, 안내원 옆 안내 데스크 |
| 2층 | 라운지 의자와 탁자 |

**비워 둘 자리** (소품을 놓지 않는다)
- 복도는 폭 12 studs 이상 뚫려 있어야 한다. 문 앞, 계단 앞, 스폰 지점 주변.
- 대정전 차단기 자리(`Config.Blackout.Breakers`의 좌표)와 그 앞 6 studs.
- 알바 표식(`Workspace.Mall.Jobs`)과 손님 NPC(`Workspace.Mall.Customers`) 주변 4 studs, 직원 NPC 주변 4 studs.
- 광장 가운데: 소동 피날레에 사람이 모이는 곳이다. 가장자리에만 둔다.

**넣는 곳**: `Workspace.Mall.Decor/<구역 이름>` 폴더(신규). 구역 모델 안에 섞지 않는다. 기존 파트를 고칠 때는 지우지 말고 색·재질·크기만 바꾼다.

## 재료 (사용자 결정: 기본 파트 + 무료 에셋 + AI 생성 도구)

세 가지를 함께 쓴다. 무엇을 쓰든 **파스텔 색, 둥글고 단순한 모양**이라는 지금 분위기에 맞아야 한다. 사실적인 사진 텍스처나 어두운 색은 쓰지 않는다.

1. **기본 파트**: 선반, 상자, 벤치, 걸레받이처럼 각진 것은 파트로 만든다. 가장 가볍고 스타일이 맞는다.
2. **무료 에셋** (Studio MCP의 `search_asset`, `insert_asset`):
   - 넣은 직후 검사한다: 안에 든 `Script`, `LocalScript`, `ModuleScript`를 **전부 지운다**. `require(숫자)`가 있으면 그 에셋은 버린다. Remote, 사운드 자동 재생, 조명, 다른 곳으로의 용접도 지운다.
   - 파트 수가 300개를 넘거나 화면에서 스타일이 튀면 쓰지 않는다. 색은 다시 칠해도 된다.
   - `Anchored = true`. 작은 장식은 `CanCollide = false`.
   - Roblox가 만든 에셋이나 검증된 제작자의 것을 먼저 고른다.
3. **AI 생성 도구** (`generate_mesh`, `generate_material`, `generate_texture`. 쓰기 전에 Studio MCP의 `list_skills`에서 관련 스킬이 있으면 읽는다):
   - 파트로 만들기 어려운 둥근 물건에 쓴다: 곰 인형, 화분의 식물, 과일, 풍선 다발, 쇼핑카트(T-109에서도 쓴다).
   - **먼저 3~5개만 만들어 캡처를 사용자에게 보여 주고**, 괜찮다는 답을 받은 뒤 더 만든다. 결과가 고르지 않을 수 있다.
4. 쓴 에셋과 생성물은 `docs/plan/assets.md`(신규)에 적는다: 에셋 id 또는 생성 프롬프트, 이름, 제작자, 쓴 곳, 검사 결과.

**성능 한도**: 이 카드로 늘어나는 파트는 1,500개 이내. 조명은 새로 달지 않는다(천장 작업으로 바꾸는 것은 예외). 작은 장식은 `CastShadow = false`.

## 진행 순서와 확인

1. A, B, C를 하고 캡처와 함께 보고한다.
2. D는 **마트 하나를 먼저** 꾸며서 전·후 캡처를 사용자에게 보여 준다. 방향이 맞다는 답을 받은 뒤 나머지 구역을 한다.
3. 구역마다 전·후 캡처를 `docs/captures/`에 날짜와 구역 이름으로 저장한다.
4. 끝나고 플레이 테스트:
   - 스폰에서 모든 구역과 2층까지 걸어서 막히는 곳이 없는지.
   - 대정전을 한 번 돌려서 배터리가 소품 속에 묻히지 않고 주울 수 있는지, 차단기 앞이 비어 있는지.
   - 알바 한 바퀴(진열, 배달).
   - 늘어난 파트 수를 세어 보고한다. 가능하면 Studio MCP 스킬 `rbx-perf-profiling`으로 한 번 잰다.
5. 확인하지 못한 것(실제 휴대폰에서의 속도 등)은 못 했다고 적는다.

## 건드리지 않는 것

- 구역의 위치와 크기, 벽, 문, 계단, `Triggers`.
- `Workspace.Mall.NPCs`, `Lights`의 폴더 구조.
- 스크립트.

## 물어볼 것

- 문 밖 풍경(A-2)을 어디까지 만들지 애매하면 가장 단순한 안(바닥과 화단)으로 하고 캡처를 보여 준다.
- 무료 에셋이나 생성물의 스타일이 기존 맵과 맞는지 판단이 서지 않으면 캡처를 보여 주고 묻는다.
