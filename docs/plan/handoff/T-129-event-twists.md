# T-129 소동 변주 ("오늘의 변수")

선행: T-126(광장 피날레). 카트 쪽 변수는 T-109 뒤에 한다(대정전 쪽은 먼저 해도 된다).

## 목적

소동을 새로 만드는 대신, **같은 소동이 열릴 때마다 조금씩 다르게** 만든다. 소동이 열릴 때 그 소동의 "변수" 하나를 뽑아 공지에 알려 주고 규칙을 살짝 바꾼다. 올 때마다 새로운 느낌을 싼값에 만든다. 근거: design-details.md 20번.

## 지금 상태

- `Config.Events`의 소동 항목: 이름, 설명, 시간, 목표, 보상.
- `EventService`가 `ReplicatedStorage.EventState` 속성(`Phase`, `EventName`, `Description` 등)으로 상태를 복제하고, 소동 모듈에 `ctx`를 넘긴다. 공지 단계에 `StartNotice(noticeCtx)` 훅이 있다.
- `HudController`의 예고 배너가 이름과 설명을 보여 준다.

## 만들 것

| 경로 | 할 일 |
|---|---|
| `Shared.Config.Events` | 소동 항목에 `twists` 목록(선택) 추가. 타입 `EventTwist = { id: string, name: string, description: string, weight: number }` |
| `Server.Services.EventService` | 변수 뽑기, `EventState`에 `TwistId`·`TwistName`·`TwistDescription` 속성, `ctx.twistId`(공지용 ctx에도) |
| `Shared.Types`, `Shared.Net` 주석 | 위 속성 반영 |
| `Server.Events.blackout`, `Config.Blackout` | 변수 4개 |
| `Server.Events.cart_chase`, `Config.CartChase` | 변수 3개 (T-109 뒤) |
| `Client.Controllers.EventController`, `HudController` | 예고·진행 배너와 결과 모달에 변수 이름 한 줄 |

## 뽑는 규칙

- 공지가 시작될 때 뽑는다. `twists`가 없으면 변수 없음.
- `NoTwistWeight = 4`(Config의 `Schedule`에 둔다)와 각 변수의 `weight`로 가중 무작위. 아래 값이면 열 번에 여섯 번쯤 변수가 붙는다.
- 같은 소동에서 직전에 나온 변수는 연달아 나오지 않는다.
- Studio 시험용: `DebugEventControl:Fire("start", "blackout", "golden")`처럼 세 번째 인자로 변수 id를 강제할 수 있게 한다.
- 변수는 **수치 하나를 바꾸는 정도**로 만든다. 모듈 안에서 `ctx.twistId`를 보고 Config의 변수용 값을 쓴다. 변수 때문에 목표가 달라지지 않게 한다(보상과 난이도 기준은 그대로).

## 대정전의 변수

| id | 이름 | 공지 문구 | 바뀌는 것 | weight |
|---|---|---|---|---|
| `golden` | 황금 배터리 풍년 | 오늘은 황금 배터리가 잔뜩! | 황금 확률 0.1 → 0.35 | 2 |
| `dim` | 약한 손전등 | 손전등 배터리가 약해요. 서로 붙어 다녀요! | 손전등 거리 42 → 26, 몸 주위 빛 9 → 14 | 1 |
| `big` | 대용량 배터리 | 배터리가 크고 무거워요. 하나가 두 칸! | 모든 배터리가 2칸짜리, 까는 개수는 절반, 든 사람의 걷는 속도 −15% | 1 |
| `zoom` | 신난 발걸음 | 정전인데 왠지 몸이 가벼워요! | 진행 중 모든 사람의 걷는 속도 +15% | 2 |

- 걷는 속도를 바꾸는 변수는 T-105의 간식 효과와 **곱하지 않는다.** 속도 배율을 한 곳(`CosmeticService`나 그 옆의 작은 모듈)에서 모아 가장 큰 증가와 가장 큰 감소만 적용하게 한다. 끝나면 정확히 되돌린다.
- `big`에서 칸 수가 홀수인 구역은 마지막 배터리가 남는 칸만 채운다(기존 황금 배터리 처리와 같다).

## 도망치는 카트의 변수 (T-109 뒤)

| id | 이름 | 공지 문구 | 바뀌는 것 | weight |
|---|---|---|---|---|
| `golden_cart` | 황금 카트 | 황금 카트가 섞여 있어요. 한 대가 세 대 몫! | 금색 카트 1대가 늘 돌아다닌다. 반납하면 3대로 친다. 다른 카트보다 15% 빠르다 | 2 |

| `herd` | 카트 대이동 | 카트가 떼로 몰려다녀요! | 동시에 도는 카트 수 +3 | 2 |

## 화면

- 예고 배너: 설명 줄 아래(또는 설명 줄을 대신해) 변수 이름과 문구. 변수가 없으면 지금과 같다.
- 진행 배너: 소동 이름 옆에 변수 이름만 작게.
- 결과 모달: 소동 이름 아래 변수 이름 한 줄.
- 새 화면 요소를 만들지 않고 기존 배너의 글자 줄만 늘린다. 휴대폰 가로에서 배너가 화면 가운데 40%를 넘어 가리지 않는지 캡처로 확인한다. `roblox-ui-ux` 스킬을 먼저 읽는다.

## 건드리지 않는 것

- 소동의 목표, 시간, 보상.
- 소동 일정(`Schedule`의 간격).

## 확인 방법

1. 변수 id를 강제해서 대정전 4개를 하나씩 연다. 변수마다:
   - 공지 배너에 이름과 문구가 보이는지(캡처 1장씩).
   - 바뀌어야 할 값이 실제로 바뀌었는지(황금 배터리 개수, 손전등 `Range`, 배터리 수와 `value`, `WalkSpeed`).
   - 소동이 끝난 뒤 값이 원래대로인지(특히 걷는 속도).
2. 변수 없이 열렸을 때 지금과 똑같이 보이고 동작하는지.
3. 가중 무작위: 뽑기 함수만 편집 모드에서 1,000번 돌려 비율이 맞는지, 직전 변수가 연달아 나오지 않는지.
4. 간식(달리기 +20%)을 먹은 채로 `zoom`(+15%)에 들어가면 속도가 19.2(더 큰 쪽)인지, `big`을 들면 감소가 적용되는지, 끝나면 16인지.
5. (T-109 뒤) 카트 변수 3개도 같은 방식으로.
6. 콘솔 오류가 없는지.

## 물어볼 것

- 변수가 붙었을 때 1인 플레이로 성공하기 어려워 보이면(특히 `dim`, `big`) 걸린 시간을 재서 보고한다. 수치는 임의로 바꾸지 않는다.
